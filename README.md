# ROS 2 录制工作台

面向 ROS 2 的中文桌面录制与数据体检软件，使用目标机器安装的 rosbag2，PyQt5 提供界面。兼容性目标为 Ubuntu 20.04、22.04、24.04 的系统 Python（3.8 及以上）；具体功能由所选 ROS 2 环境及其插件决定。

## 启动

使用 deb 安装包时，在包所在目录运行 `sudo apt install ./ros2-recorder-desktop_0.7.0-1_all.deb`，然后在应用菜单搜索“ROS 2 录制工作台”，或运行 `ros2-recorder`。需要补齐 ROS 组件时运行 `ros2-recorder-setup`，没有 ROS 2 则运行 `ros2-recorder-setup --install-ros`。deb 不包含 ROS 2 本体、设备驱动或自定义消息源码。完整迁移步骤见 [安装说明](INSTALL.md)，本次改动见 [v0.7.0 发布说明](docs/release-notes.md)。

首次安装或补齐依赖，在软件目录运行：

```bash
./install.sh
```

如果目标机器还没有 ROS 2，运行 `./install.sh --install-ros`。脚本按当前系统选择基础环境，也支持指定已有 ROS 2 版本或自定义路径。安装完成后，在应用菜单搜索“ROS 2 录制工作台”。详细选项见 [一键安装说明](INSTALL.md)。

只检查、不修改系统：`./install.sh --check`；只预览步骤：`./install.sh --dry-run`。

启动软件：

```bash
./launch.sh
```

或运行 `python3 install_launcher.py` 添加当前用户的应用菜单入口，随后搜索 **ROS Recorder / ROS 2 录制工作台**。菜单入口指向本目录，移动目录后需要重新安装入口。

如果要使用启动终端中加载的额外 ROS 环境，先加载它，再运行启动脚本。软件不会自动开始录制。

主界面随窗口大小调整，不使用整页滚动条。话题列表与日志分别在区域内滚动；拖动两者之间的分隔条可调整高度。右侧录制配置独立滚动，展开高级参数不会把开始/停止按钮或状态挤出窗口。长环境路径和录制路径会缩略显示，悬停可查看完整内容。

“目录剩余空间”使用十进制 GB 显示（1 GB = 1,000,000,000 字节），便于与文件管理器对照。

其他机器所需组件：`python3-pyqt5`（5.14 及以上）、`python3-yaml`、`python3-numpy`、`python3-colcon-common-extensions`，以及目标 ROS 2 发行版的 rosbag2；使用 MCAP 还需该环境支持并安装相应存储插件。建议使用系统 `/usr/bin/python3`，避免 ROS 二进制包与虚拟环境不兼容。软件不包含 ROS 2 本体。

## 环境与版本适配

- 优先使用启动软件时已经加载的 ROS 2 环境；未加载时，自动查找 `/opt/ros` 下唯一的 ROS 2 安装，不会固定加载某个发行版，也不会将 ROS 1 当作 ROS 2。
- 安装了多个 ROS 2 版本时，在“消息环境 → 基础 ROS 2 环境”中选择并加载；自定义安装也可直接填写基础环境 `setup.bash` 的完整路径。所选基础环境会随配置保存。
- 也可通过 `ROS2_RECORDER_SETUP=/完整路径/setup.bash ./launch.sh` 明确选择基础环境，或通过 `ROS2_RECORDER_PYTHON` 指定与 ROS 2 匹配的 Python 解释器。
- 软件检测当前 `ros2 bag record --help` 和存储插件，适配实际支持的选项。不可用的选项会禁用；导入配置若要求无法支持的功能，开始前明确报错，避免悄悄丢弃设置。
- 某些早期录制器的缓存按**消息条数**计算，此时界面显示“缓存消息数”。较新的实现按字节数计算，界面用十进制 MB 和精确字节显示。已有方案的容量保留原字节数，编辑容量时按原有步长取最接近的值。
- 自定义消息的编译缓存按源目录、ROS 2 环境和 Python 版本分开。移到其他 Ubuntu / ROS 2 环境时，应重新编译自定义消息，不能直接复用另一环境的二进制编译结果。

## 使用流程

1. **消息环境**：标准消息可直接使用。已有编译产物时，在“加载已有编译环境”中选择 `install/setup.bash`，也可在输入框填入 `install` 目录或上一级工作空间。加载和录制需要完整的安装产物及其依赖，可部署到没有 `src` 的目标机。需要从源码编译时，选择包含 `src` 的工作空间或包含 `package.xml` 的消息包目录，扫描并勾选消息包，再点“编译并加载”。软件会构建选中包及其工作空间依赖，并检查消息类型支持。
2. **话题与频率**：仅录制列表中已勾选的话题。搜索框按话题名称和消息类型筛选显示，支持忽略大小写的关键词；搜索不改变勾选状态，搜索结果外已勾选的话题仍会录制，数量会明确提示。“全选当前结果 / 取消当前结果”只操作当前可见行。名称与消息类型分列单行显示，长文本悬停查看；列表显示当前实际发现的话题，以及本次运行中手动添加的话题；方案中尚未发现的话题不生成占位行，也不计入列表中的已勾选数，发现后按方案自动勾选。手动添加的话题会立即显示，消息类型标记为“手动添加，未发现”，发现后替换为真实类型；可以取消勾选，重复添加不会产生重复行。发现可识别的话题后默认检测接收频率，悬停频率可查看帧间隔和标准差；可逐个关闭，或取消“自动检测频率”停止全部检测。手动关闭的话题刷新后不会重新开启。准备录制时会先停止检测并等待进程退出，录制期间禁用检测，停止并保存后恢复此前开启的话题。
3. **录制配置**：选择 SSD 或移动硬盘上的保存目录，设置缓存、存储格式、预设及分包大小。缓存单位及可用选项以当前环境为准。高级选项包含 QoS YAML、存储 YAML、压缩队列、仿真时间和磁盘预留空间。
4. **开始 / 停止**：开始前检查已发现话题的类型和存储插件。停止时发送 SIGINT，等待缓存写完和 rosbag 退出，再生成报告并弹出汇总：录制名称、保存位置、有消息/已登记话题数、bag 数据时长、消息总数，以及各话题消息数和估算平均频率；支持打开保存目录、复制汇总。平均频率使用各话题消息数除以 bag 首末消息间隔，包含话题起停差异。空录制和保存异常会明确提示；退出软件时不再弹出汇总。等待超过 15 秒会出现手动强制停止入口；强制停止的记录会标记为失败。
5. **录制记录**：查看话题消息数、估算均频、告警及原始日志；可复用任意一次录制配置，或点击“离线统计所选 bag”进入统计窗口。
6. **数据分析**：在“选择话题”弹窗勾选并确认，主表只显示已选话题最新收到消息的 `header.stamp`；选择一个基准，其余话题显示相对它的时间差（ms）。支持相机、毫米波雷达、激光雷达等不同消息类型，无需播放或等待扫描 bag。
7. **配置管理**：保存多个命名方案，支持 JSON 导入导出和常用 `ros2 bag record` 命令导入。命令导入只解析受支持的参数，不执行粘贴的文本；不支持的参数会明确拒绝，不会丢弃。原始缓存和分包字节数会保存在高级设置中，修改对应容量设置会清除字节覆盖值。

在“消息环境”中点击“清除自定义环境”可切回基础 ROS 2。未加载自定义类型时仍可开始录制，类型检查告警会显示在录制日志界面并写入报告。需要缺失类型支持的话题可能无法写入 bag。

“录制日志”右侧的“清除日志”可手动清空当前界面日志，方便开始新一轮录制前整理显示；不会清除磁盘上的 `recorder.log`、录制报告或告警计数。录制期间清除后，新日志仍会继续显示。

界面不再提供全部话题、正则匹配或排除规则。加载历史配置/命令时会保留显式话题列表，旧的全部话题/正则/排除配置会作为参数方案加载，保留当前勾选，不清空选择也不自动扩大录制范围。新发现的话题不会自动加入录制范围。

加载方案时，若基础环境、自定义环境路径及消息包选择均与当前一致，会直接复用已加载环境；切换环境时加载按钮暂时禁用，成功或失败后恢复。普通话题发现不会阻止应用方案参数。

录制目录命名为“自定义前缀_年月日_时分秒”，例如 `capture_20261030_174306`。仅在数据目录或日志报告目录重名时追加 `_1`、`_2` 等序号，避免覆盖已有数据。QoS 与存储 YAML 会在开始时复制为快照，本次录制使用快照。

## 实时消息时间戳

进入“数据分析”即可看到本机当前系统时间（Unix 秒）。点击“选择话题”，在弹窗中按消息类型筛选、搜索关键词、刷新并勾选需要监听的话题。确认后点击“开始监听”，主表显示已选话题的最新 header 时间戳、本机接收时间、相对基准的差值（ms）与接收状态。监听期间可以重新打开弹窗修改选择，确认后才更新订阅，取消则保留原有选择和基准。消息类型按当前发现的完整类型列出，常用 PointCloud2、Image、CompressedImage 等优先显示，也支持自定义 msg。类型筛选与关键词搜索共同生效，切换筛选时保留勾选。

默认差值为“最新收到消息的 header 时间 − 本机收到该条消息时的系统时间”。该差值随新消息更新，并包含传输和接收处理耗时。可在“比较基准”切换到已选话题，比较两条最新消息的 header 时间。差值保留正负号，切换基准立即重算。新到消息的时间戳即使倒退，也会替换旧显示值。没有有效 header 时差值显示“—”。没有 header、类型未加载、未收到消息和长时间未更新会分别提示。

此处比较各话题当前最后收到的一条消息，不做帧配对，也不自动证明硬件同步。不同发布频率会使差值跳动。详见 [实时消息时间戳说明](docs/live-stamps.md)。底层复用 ROS 原生 raw 订阅及解码，标准首字段 Header 的 CDR1 消息只提取时间前缀，避免完整解码图像 / 点云 / 轨迹数组。

在“对照监听设置”中可选择 Best Effort 或 Reliable、队列深度、每轮监听时长及 Fast DDS 传输方式。先监听一轮并设为基线，再用另一组设置监听，在“查看通信对照”中按话题比较接收频率、最长间隔和帧龄。

排查偶发断帧时，可以在已加载 ROS 2 的终端运行 `python3 -m ros2_recorder.lidar_monitor`。默认同时监听本机的 ZVLiDAR 和 Seyond，按 DDS 发布时间对比 Best Effort 和 Reliable，并将逐帧时间戳、断流、监测端取帧延迟、网口计数、UDP 接收队列丢包、ROS 告警及 PTP 服务日志写入 `~/lidar-monitor-logs/`。按 Ctrl+C 结束，或用 `--duration 120` 指定秒数。其他 PointCloud2 雷达可以重复传入 `--stream /话题,网口,UDP端口`。日志里的 `qos_difference` 表示同一帧在 2 秒内只被一侧收到，`end` 行包含全程统计。

管理员侧栏的“通信环境”与“设备授时”“点云标定”同级。可配置 Fast DDS 共享内存和 UDP、设为当前 Linux 账户的默认配置、撤销默认项，或导出 XML 和启动命令。模块内可检查当前 ROS 2 环境、运行进程实际映射的中间件和共享内存、话题 QoS，并查看感知、融合、控制、录包和跨机传输的配置说明。

监听前暂停既有的频率检测订阅，停止后恢复。监听与录制互斥，退出会停止辅助进程。没有新增 bag 播放流程。

## 离线数据分析

离线统计保留在“录制记录 → 离线统计所选 bag”的独立窗口。打开 bag 仅显示话题列表，勾选后点击“读取所选”才扫描；不自动扫描全部话题。读取和导出支持取消。可查看五项指标：

- **频率**：用 `header.stamp` 计算相邻消息的正间隔，频率为平均正间隔的倒数；曲线按时间窗口统计，上方显示整个话题的结果。
- **消息数**：上方显示实际扫描的消息总数（包含没有有效 header 的消息）；曲线按 header 时间窗口显示有效消息数。
- **最长 / 最小间隔**：相邻有效 header 的差值，曲线分别显示每个窗口的最大 / 最小间隔，单位 ms。包含零和负值，便于识别重复时间和时间倒退。频率仅使用正间隔。
- **时间戳分布**：每个话题一行，落点来自逐条 `header.stamp`，空白处表示该时间段没有对应的消息时间戳。缩放后会重新查询原始 header 时间，游标显示精确的秒与九位纳秒。

分析使用 **消息内 header 时间**，没有 header、零 / 无效时间戳、消息类型未加载或解码失败时明确提示，时间统计不会改用 bag 时间。消息数仍可查看。回放按 bag 记录时间安排发布，两种时间用途分开。首次有效 header 所在秒作为横轴的公共起点；不同设备的时钟基准是否相同仍需用户确认，叠加显示不代表已经同步。

勾选多个话题即可比较同一指标。滚轮缩放、拖动平移、双击恢复全部范围，单击固定 / 解除游标。曲线最多保留 600 个时间窗口，短包窗口为 1 秒，长包会自动加宽；窗口宽度可悬停曲线查看。时间戳分布使用独立的只读输入、临时索引查询：每个显示窗口保留实际时间戳的首末及计数，放大后补充细节，不把抽样点数当作实际消息数。

支持完整 bag 目录及单个 SQLite3 / MCAP 文件；打开单文件不包含其他分包。无元数据的目录仅在找到一个存储文件时按单文件打开，多分包目录需要完整元数据。文件缺失、类型冲突、SQLite WAL 未完成保存等情况会明确提示。扫描前后检查文件大小和修改时间，输入发生变化时结果作废。

读取和解码在所选 ROS 环境的独立进程运行，不创建 ROS 节点，不修改原始 bag。扫描需要 `rosbag2_py`、对应存储插件及消息类型；自定义消息在“消息环境”加载。完整 header 时间索引只保存到临时工作目录，关闭或更换结果后清理。MCAP 内部块压缩由存储插件读取；首版暂不扫描 rosbag 外层 `file` / `message` 压缩，需另存解压或转换后分析。

“导出”生成 JSON 汇总和同名 `_anomalies.csv`，保留时间来源、整数纳秒、对应 bag 时间等信息。异常 CSV 记录重复时间和读取顺序中的 header 时间倒退；界面不再要求设置期望频率和间断阈值。没有异常时仍生成 CSV 表头。导出文件先写临时文件再替换，两个输出文件不构成跨文件原子事务，失败时按提示重新导出。

读取失败或取消保留上次成功结果；打开另一份数据会清除旧结果。首版录制、环境变更与分析互斥，退出时取消分析并清理进程。任意嵌套消息字段 / 数组的通用对比尚未加入；点云手动标定见 [点云标定说明](docs/manual-calibration.md)，其余预览和标定扩展见 [后续计划](docs/analysis-roadmap.md)。

## 频率、缓存与完整性

- 实时 Hz 是独立订阅者在本机观察到的接收频率，不是发布端计数，也不是 bag 的写入频率。采用 best effort 传感器 QoS、原始序列化订阅，最近 5 秒内最多统计 2000 个样本；超过 2 秒没有新消息会提示。低频或间歇发布话题也可能正常出现该提示。
- 所有频率检测共享一个 ROS 进程，取消此前同时 8 个话题的限制。每次启动默认开启自动检测，旧配置中的关闭状态不会覆盖启动默认值；本次运行中手动关闭后，切换录制配置也不会重新打开。可通过总开关或逐个关闭控制。图像和点云检测仍会增加 DDS 接收负载；录制准备与进行期间会停止检测、释放检测订阅，避免与录制争抢资源，保存结束后恢复。
- 空闲时约每 5 秒在后台自动刷新话题，按钮保持“刷新话题”；只有手动点击才显示“正在发现…”。若后台正在发现，手动点击会等待同一次发现结果，不重复启动。驱动稍后上线也能被发现并启动检测；录制期间暂停自动刷新。方案中尚未发现的话题只保留在录制配置中，不生成占位行；手动添加的未发现话题会显示明确标记；已发现但消息类型不可用的话题显示“类型未加载”，悬停按钮可查看原因；发现话题与选择录制相互独立，不会自动勾选新话题。
- 文件增长速率来自 bag 文件大小变化，受 rosbag/文件系统缓存、分包和压缩影响，不是实际磁盘设备写速。
- 目录测速写入约 134.22 MB 临时数据、执行同步后删除，只提供短时参考，不代表持续写速或高负载录制能力。
- 当前录制器声明使用双缓冲时，峰值缓存内存可能约为字节设置值的两倍，另有进程和消息开销；消息条数缓存的内存取决于实际消息大小。缓存不能补偿持续不足的磁盘写速。
- 默认预留约 5.37 GB，低于阈值会请求停止并等缓存写完；这不保证剩余空间足够写完所有缓存，阈值需要结合数据量设置。
- MCAP `fastwrite` 优先吞吐，省略消息索引及部分校验；高效检索或跳转可能需要录后转换补建索引。`zstd_fast` 用块压缩节省空间，但需评估 CPU 开销。
- 录制日志与元数据不能证明整个链路零丢帧。报告始终保留“完整性未验证”。录后估算均频是话题计数 / bag 全局时长，不能单独判断丢帧。

当前分析使用消息内 header.stamp；后续跨话题同步分析会明确话题配对规则和允许误差。

接口副本帮助后续排查和重建消息环境，不代替完整工作空间及其依赖备份。bag 可移到其他机器；读取端需要支持对应格式、元数据版本和消息类型，不能保证任意新旧 ROS 2 版本直接互读。

命名方案与上次配置：`~/.config/ros2-recorder/profiles.json`（遵循 `XDG_CONFIG_HOME`）。

管理员入口：连续点击左上角“ROS Recorder”六次（相邻点击不超过 1.5 秒，点击其他位置会重置计数）。首次进入需设置至少 6 个字符的密码，以后验证密码后进入管理员设置，并在“数据分析”下方显示“设备授时”“点云标定”“通信环境”和“管理员设置”。点云标定集成双 PointCloud2 手动外参调整，直接订阅 ROS 2 话题，无需启动旧 RViz 工具。管理员设置可修改密码或退出，重启后也会隐藏这些入口。

“设备授时”列出以太网口、链路、硬件时钟和开机自启状态。勾选网口后点击“保存并启用”，经 Linux 管理员授权将该口的配置写入 `/etc/systemd/system/ros-recorder-timing-网口.service` 并启用。授时由 systemd 管理，退出录制软件后继续运行，车机重启后自动启动，异常退出后自动重试。勾选对应网口并点击“停止并关闭自启”可停止授时，保留配置供下次启用。需要 `linuxptp`、`ethtool` 和提供桌面授权的 `pkexec`。已有成对部署的 `ptp4l-网口.service` / `phc2sys-网口.service` 使用各自的 Linux 配置。录制准备和录制期间禁用启停。

选中行可配置 PTP 域、UDPv4 或 L2、标准 PTP 时标或旧设备 UTC 兼容模式。延时机制为 E2E。UDPv4 需要该网口已有 IPv4 地址。新服务启动时会将网口置为 UP，停授时保留网口的网络连接。共享同一个 PHC 的网口暂不能同时独立授时。

验收时看该行的链路、PTP 主端口、PHC 偏差与 Sync 计数是否增长。Delay_Req 增长表示收到设备的请求。日志采集需要当前 Linux 账户能读取对应服务日志。可在网口配置中填写 Seyond Falcon 的 IPv4 地址，软件会从所选网口查询设备是否报告 PTP 锁定，需要 `curl`。其他设备需用厂商工具确认锁定。本机发包和设备报告锁定是两项独立的检查。

标定操作与旧 INI 兼容规则见 [手动标定说明](docs/manual-calibration.md)。标定页会在后台自动刷新点云话题，保留手动刷新按钮；选择某一路后自动订阅，切换或清空选择自动更新订阅。暂停由外部播放器或数据源控制。离开标定页或退出管理员模式时自动停止订阅；订阅期间暂停原频率检测，并阻止启动录制或切换消息环境，停止后恢复。

管理员密码使用随机盐和 PBKDF2-SHA256 摘要，保存在 `~/.config/ros2-recorder/admin.json`（遵循 `XDG_CONFIG_HOME`），不保存明文，不随录制配置导出。这是本机应用内的入口保护，不能限制拥有本机账户或配置文件修改权限的人员。

安装配置：`~/.config/ros2-recorder/installation.json`。未加载 ROS 2 且未指定其他环境时，用作基础环境选择；已有录制配置中的显式环境选择仍保留。

消息编译输出：`~/.cache/ros2-recorder/workspaces/源目录标识/builds/本次构建标识/`（遵循 `XDG_CACHE_HOME`）。每次使用新构建目录，失败的编译不覆盖先前已加载的结果；配置引用的构建目录需要保留。

## 结构与扩展

- `config.py`：参数验证、命令解析和配置持久化。
- `compatibility.py`：录制参数、压缩模式、存储插件和缓存单位检测。
- `installer.py` / `install.sh`：依赖检查、按需安装、官方 ROS 2 源配置、工作空间 rosdep 依赖安装和应用菜单配置。
- `environment.py`：工作空间识别、编译命令、环境加载与类型校验。
- `probe.py`：独立 ROS 进程中的话题发现、频率统计和最新时间戳订阅，不在界面进程中热加载消息库。
- `frequency.py`：共享频率检测进程及动态话题订阅控制；录制前停止并等待检测退出，保存结束后恢复。
- `processes.py`：进程组管理与停止信号。
- `recording.py`：录制会话、配置快照、空间监控、元数据报告。
- `app.py` / `tasks.py`：桌面界面和后台任务桥接。
- `admin_access.py` / `admin_ui.py`：本地管理员密码、隐藏入口及密码窗口。
- `calibration_page.py` / `calibration_view.py`：管理员点云标定页、内置三维点云视图与选点属性。
- `calibration_math.py` / `calibration_cloud.py`：外参、旧 INI 厘米换算、PointCloud2 字段及行填充处理。
- `calibration_monitor.py` / `calibration_probe.py`：独立 ROS 订阅进程与有限点数预览；不发布点云或外参话题。
- `latest_stamps.py` / `stamp_probe.py` / `live_stamp_page.py`：最新到达消息的 header 订阅、基准差值与实时表格。
- `header_stamp.py`：复用 ROS 原生时间解码器的前缀提取和安全回退。
- `analysis.py`：独立进程中的只读 bag 读取、header 解码、流式统计、时间戳索引和异常 CSV 生成。
- `analysis_job.py` / `analysis_page.py` / `analysis_chart.py`：分析进程生命周期、取消与导出、单指标交互图表及话题选择页面。

后续预览与同步分析在独立分析模块上扩展，复用消息环境与数据集信息，无需改变录制引擎。

### 话题可靠性与录制 QoS

话题表的“发布可靠性”列显示 Reliable、Best Effort、混合、未知或无发布端；这是 ROS 2 QoS 可靠性，不是 TCP/UDP 类型。测频订阅会跟踪发布端变化：所有已发现发布端均为 Reliable 时采用 Reliable，否则采用 Best Effort。鼠标悬停接收频率可查看实际测频订阅可靠性。

“录制可靠性”默认为自动适配，由 rosbag2 按各话题发布端选择；也可对勾选的话题统一指定 Reliable 或 Best Effort。强制 Reliable 前会检查已发现的 Best Effort 发布端并阻止不兼容的录制。之后新出现或更改的发布端仍需核对录制日志。指定模式会生成本次会话的 recording_qos.yaml 并保存在 .recorder_sessions 中，配置方案保留该选择。高级自定义 QoS YAML 与指定模式不能同时使用；使用自定义 YAML 时请选自动适配，此时 YAML 中指定的策略优先。Reliable 不能保证驱动、应用和磁盘整条链路不漏帧，仍需核对录包计数与采集时间戳。


### 可选 YAML 模板

高级参数中的 QoS YAML 和存储 YAML 分别有“启用”勾选框、浏览、编辑和默认文件入口。未勾选时保留路径但不读取、验证或传入录制器；保存编辑也不会自动启用。首次启动会在 `~/.config/ros2-recorder/templates/`（遵循 XDG_CONFIG_HOME）创建 `qos.yaml`、`sqlite3.yaml` 和 `mcap.yaml`，已有文件不会被覆盖。“默认文件”只选择默认路径，不重置已编辑内容。切换存储格式时仅自动切换默认存储文件，自选文件保留。旧配置和导入命令中明确指定的 YAML 仍按启用状态加载。

QoS YAML 按完整话题名配置 reliability、history、depth、durability。默认模板为 `{}`，保持自动适配，注释内提供 `/iv_points` 示例（使用时删除 `{}` 并取消示例注释）。sqlite3 使用 `write.pragmas` 列表，默认空列表沿用插件/预设参数。MCAP 使用 `chunkSize`、`compression` 等大小写敏感字段，默认模板保留索引和块校验、不压缩。存储 YAML 的显式参数会覆盖相应存储预设，请使用与 sqlite3/MCAP 对应的文件。启用的文件在每次录制时保存独立快照。

格式参考：[ROS 2 QoS 配置](https://github.com/ros2/rosbag2#overriding-qos-profiles)、[sqlite3 存储配置](https://github.com/ros2/rosbag2/tree/rolling/rosbag2_storage_sqlite3)、[MCAP 存储配置](https://github.com/ros-tooling/rosbag2_storage_mcap#writer-configuration)。
