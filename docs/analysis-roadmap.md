# 数据分析、回放、预览与标定实施计划

状态：当前优先交付实时消息时间戳：勾选话题、查看最后收到的 header.stamp、选择基准比较毫秒差值。不实施播放；离线图表保留为录制记录中的独立窗口。日期：2026-11-02。

## 目标与实施顺序

围绕同一份 bag 建立“检查数据 → 回放复现 → 查看内容 → 检查同步 → 标定与验证”的流程。先交付数据体检与基础回放，再逐步增加预览、同步分析和标定。每一阶段独立验收。

现有基础：PyQt5 桌面界面、ROS 环境选择、自定义消息环境、SQLite3 / MCAP 录制、录制会话与报告、独立 ROS 辅助进程。当前数据分析页为实时消息时间戳表格；离线分析保留在独立窗口，录制报告仍主要来自 metadata.yaml。

## 第一阶段：数据体检

交付内容：

- 从录制记录进入分析，或打开外部 bag 目录；在后端支持时接受独立存储文件。
- 先读取元数据展示格式、大小、总时长、话题类型及消息数，再按用户选择扫描话题。
- 按话题展示首末时间、覆盖时长、平均频率、帧间隔统计、最长间断。
- 展示固定时间窗口消息数、帧间隔曲线及异常列表，点击异常定位图表时间范围。
- 支持期望频率、间断阈值配置；明确区分阈值告警与已证实的丢帧。
- 显示进度，支持取消；导出 JSON 汇总与 CSV 异常明细。

修订后的统计约定：分析使用消息内 header.stamp，回放使用 bag 记录时间；频率为平均正间隔的倒数。最大 / 最小间隔包含零和负值；无效 header 不参与时间计算。消息总数仍包含全部实际读取消息，另列有效 header 数、无效数及解码失败数。无 header 或类型未加载时不改用 bag 时间。时间计算使用整数纳秒，原始 header 时间戳旁路索引支持缩放查询。

验收：已知 header 频率及间断得到预期结果，bag 时间与 header 时间刻意不同时分析仍跟随 header。覆盖空包、单消息、分包、缺少元数据、缺插件、类型缺失、无 header、零 header 和解码失败；扫描可取消，界面保持响应。消息计数可直接读取，header 时间分析需要反序列化。

## 第二阶段：基础 ROS 回放

交付内容：

- 复用已打开的数据集，选择话题、倍速、循环及回放 Domain，支持开始与停止。
- 检测当前 ROS 环境的回放能力，按能力开放暂停、继续、进度及跳转。不得以计时器估算值冒充实际播放位置。
- 回放开始前明确展示发布目标，默认提供独立的回放 Domain 配置；检查本应用当前录制与回放的 Domain 冲突。
- 提供外部 RViz / 算法连接到该 Domain 的环境说明。
- 管理独立进程组，正常停止及退出时清理进程；保留错误输出。

第一版采用明确的操作约束避免录制到本应用回放的数据。独立 Domain 仅减少误接收，不保证该 Domain 没有其他参与者。

验收：选定话题能被隔离 Domain 中的测试订阅者收到；停止后不再发布；循环、倍速符合实际支持能力；不支持的控制明确禁用；退出应用后没有遗留播放进程。

## 第三阶段：图像与点云预览

交付内容：

- 在应用内直接读取并显示消息，提供统一时间轴、拖动定位、单帧前进后退和时间戳显示。
- 图像先支持常见 sensor_msgs/Image 编码和 CompressedImage，显示尺寸、编码及消息时间。
- 点云先支持 PointCloud2 XYZ，提供缩放、旋转、平移和坐标轴；再增加强度 / 高度 / RGB 着色。
- 图像和点云共享当前查看时间，支持参考话题选择与容差，并显示实际帧时间差及无匹配状态。
- 显示 frame_id，保留静态 / 动态 TF 接入位置。没有坐标变换时，单独显示各自坐标系，不声称已经空间对齐。

应用内预览的播放是本地时间轴控制；ROS 回放是向外发布消息，两者状态及控制分开。预览不要求启动 ROS 回放。

点云渲染实现前验证目标机的 Qt / OpenGL 兼容性，采用按需安装的可视化依赖。显示时可降采样，统计、导出和后续标定仍使用原始数据。

验收：支持的图像编码显示正确；点云正确处理字段布局、数据类型、字节序和有组织点云；无效点不会导致崩溃；未支持编码和字段给出明确原因；连续拖动时间轴不积压解码任务。

## 第四阶段：跨话题同步分析（header 时间读取已提前完成）

交付内容：

- 在已有 header.stamp 分析上增加自定义消息时间字段，并在报告中明确来源与单位；bag 时间用于回放及辅助对照。
- 检查零时间戳、重复、倒退及异常跳变。按后端实际读取顺序解释结果，不把按时间排序后的读取结果当作原始写入顺序证据。
- 按任务配置最近邻、一对一或时间窗口覆盖等匹配规则，记录容差和预期时间偏移。
- 展示时间差曲线、分布、分位数、匹配率、超差比例和漂移趋势。
- 导出匹配明细及规则，支持在预览中检查异常片段。

只有确认时钟基准可比后才解释时间差。没有硬件同步或采集端证据时，不将时间差直接称为传输延迟。高频 IMU 与相机优先采用帧间窗口覆盖检查。

验收：已知偏移、漂移、重复时间戳和不同频率的数据得到预期分析；匹配规则中的消息复用与边界行为有明确测试。

## 第五阶段：标定工作流

建议优先级：单目相机内参 → 激光雷达与相机外参 → 双目及其他传感器组合。具体顺序在进入本阶段前根据设备和任务确定。毫米波雷达与相机、相机与 IMU 等需要单独设计采集和求解流程。

相机内参：

- 创建标定项目，配置标定板类型、尺寸和单位。
- 从 bag 选帧、检测角点、提示覆盖不足并剔除明显无效样本。
- 求解内参、畸变参数，展示整体与逐帧重投影误差、去畸变预览。
- 用保留样本验证结果，导出含图像尺寸和畸变模型的参数。

激光雷达与相机外参：

- 优先采用有标定板的受控采集流程，先定义目标物、对应特征和数据要求。
- 复用时间配对、图像和点云预览，确认相机内参及时间关系。
- 求解外参，以多帧点云投影和独立验证帧检查效果。
- 输出变换矩阵、旋转 / 平移、源与目标坐标系、单位及变换方向，避免方向歧义。

标定结果连同输入数据引用、样本选择、算法版本、配置和验证误差保存为项目。数据条件不足时返回具体原因，不生成看似有效的结果。自动覆盖设备参数、在线发布 TF 和写入设备不属于首版标定范围。

## 共用架构与数据约定

- 数据集层：统一 bag 标识、话题信息、分包文件与能力检测，提供按话题顺序读取、时间定位及批量扫描接口；无索引时声明限制，可按需构建旁路索引。
- ROS 辅助进程：复用当前环境加载方式，将 bag 读取、消息解码与回放放在独立进程，隔离 ROS Python 和消息库。
- 时间轴层：保留原始整数纳秒、时间来源、参考话题、配对规则和偏移；禁止静默用 bag 时间替代缺失的消息时间。
- 作业层：统一进度、取消、错误和输出协议；图表使用有界采样，完整异常流式写出，缓存设置容量限制。
- 页面层：将分析、回放和预览控件放入独立模块，app.py 保留导航与流程衔接，避免继续集中增加业务代码。
- 项目与缓存：分析、预览索引和标定结果独立保存，输入数据身份、配置和结果格式带版本；修改或移动数据后重新校验缓存。用户可选输出目录，支持只读 bag 来源，不修改原始 bag。
- 资源调度：录制优先。第一版录制与重扫描 / 回放互斥；后续再依据磁盘和 CPU 压力增加并行策略。不要承诺通过暂停一个普通线程即可可靠暂停所有 ROS 读取。
- 兼容性：保持 Python 3.8+ 及当前目标 Ubuntu / ROS 环境要求；逐项检测读取、存储、压缩、回放和定位能力，记录实际验证范围。

## 首轮实施范围

评审通过后先实现第一阶段，再实现第二阶段，每阶段完成后提供可运行版本与验证结果。首轮为统一数据读取、时间轴和后续预览留接口，不提前实现标定求解。

先做适配性验证，确认本机 ROS 环境的 SQLite3 / MCAP 读取与回放控制能力，再接入 UI。使用可控合成数据验证分析统计，使用隔离 Domain 验证真实回放；保留现有录制测试，确认新增功能不影响开始、停止、环境加载和报告生成。
