# ROS Recorder v0.5.0

发布日期：2026-11-05。

本版新增发布端 QoS 可视化、录制可靠性选择和可编辑 YAML 模板，修正 Reliable 点云话题使用 Best Effort 测频可能漏收消息的问题。

## 改动

- 话题表新增“发布可靠性”：显示 Reliable、Best Effort、混合、未知或无发布端，并区分发布端与测频订阅的可靠性。
- 测频订阅定期检查发布端：全部明确提供 Reliable 时请求 Reliable，否则采用 Best Effort；可靠性变化后重建订阅并重置采样窗口。
- 录制配置新增“自动适配 / Reliable / Best Effort”。自动适配由 rosbag2 分话题选择；指定模式为所选话题生成独立 QoS 文件并保存在会话目录。
- 强制 Reliable 前检查已发现的 Best Effort 发布端，发现不兼容时阻止启动。录制中后续出现的发布端变更仍需核对日志。
- QoS YAML 和存储 YAML 新增独立启用开关、默认文件、浏览和编辑入口。未启用的文件保留路径，但不读取、不验证，也不传入录制器。
- 首次启动创建用户级 qos.yaml、sqlite3.yaml 和 mcap.yaml 模板，不覆盖已有修改；切换存储格式仅自动切换默认存储模板，不改动自选路径。
- 旧配置及导入命令中明确指定的 YAML 保持启用；配置方案保留可靠性、路径和开关。启用文件在录制启动时保存快照。

## 使用和安装

```bash
sudo apt install ./ros2-recorder-desktop_0.5.0-1_all.deb
```

升级后重新打开软件。YAML 位于高级参数中，新配置默认不启用。默认 QoS 模板不覆盖话题策略；sqlite3 模板沿用插件/预设参数；MCAP 模板保留索引和块校验、不压缩。使用示例前请阅读模板注释。

## 验证与范围

在本机 ROS 2 Humble 完成配置与界面测试、Reliable/Best Effort 混合发布测频测试、强制 Reliable 真实录包及默认 sqlite3/MCAP YAML 模板录包验证；有限序号消息录后逐条解码检查完整性。其他 ROS 2 发行版和目标设备仍需实机验证。

Reliable 提高传输完整性，不保证驱动、应用、磁盘整条链路不漏帧；接收频率不代表录包完整性。点云标定、数据分析及管理员功能保持原有范围，设备授时仍为预留入口。

ROS 2、设备驱动和私有消息包由目标机器提供；deb 不包含个人配置、录制数据或编译缓存。
